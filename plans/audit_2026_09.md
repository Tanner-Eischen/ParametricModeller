# Parametric Modeler Audit — September 2026

**Date:** 2026-09-05
**Scope:** Compare current `parametric-modeler` (v0.2.0 / Milestone 07+) against professional parametric CAD tools (Fusion 360, Onshape, SolidWorks, FreeCAD, SketchUp Pro, Rhino 7), identify feature gaps and UX pain patterns, and produce a prioritized recommendation list.
**Why this exists:** The project aims to be a viable woodworking CAD tool, but the current scope is limited — only planar/prismatic geometry, no curves, no fillets, no chamfers, no revolves, no simulation. Before expanding feature breadth we should know what professionals expect and where the current implementation falls short.

---

## Executive summary

The modeler is well-architected at the **core**: deterministic rebuild, stable topology IDs, B-Rep planar geometry, history-based parametric features, planarity guards, signature-based fallback matching, and a focus on the woodworking niche. The `App.ts` is **9,432 lines** and test coverage is **1,105 unit tests** with green e2e on the main tool flows. Phases 0–6 of the professionalization roadmap are essentially complete.

**However**, the product is missing many features that users of professional CAD tools consider table stakes. The biggest gaps are not algorithmic (the B-Rep kernel and rebuild pipeline are solid) but **breadth of features** and **discoverability of existing features**. Below is the full audit with prioritized recommendations.

**Verdict:** Don't add breadth yet. **Close the top-5 UX gaps** and **ship one wave of high-value missing features** (fillet, chamfer, shell, hole) before expanding further. The current state would frustrate a professional user on day 1 not because of bugs but because of missing operations and opaque UI.

## 1. What is built (the strengths)

This section establishes what the audit should NOT recommend rebuilding.

### Core engine (Phase 0–2, complete)

- **Deterministic, history-based rebuild pipeline** with `RebuildContext`, `RebuildEngine`, `DependencyGraph`, and per-feature instrumentation.
- **Stable topology IDs** (`TopologyIdAllocator`) with **signature-based fallback matching** (Milestone 08) and `getReferencedFeatureId` resolver.
- **Centralized tolerance policy** (`TolerancePolicy`) used by every kernel.
- **Planar B-Rep geometry core** (`Body`, `Face`, `Edge`, `Vertex`, `Plane`, `ConstructionPlane`, `CoordinateFrame3D`) with validation, triangulation, and the `PrismaticBoolean` kernel.
- **Sub-object references** (`SubObjectTypes`) covering body, face, edge, vertex refs with stable IDs across rebuilds.

### Features (Milestone 01–07, complete)

- Primitives: `box`.
- Sketch + extrude + extrude-cut (with face-based cuts).
- Sketch constraints: horizontal, vertical, coincident, parallel, perpendicular, equal, fixed, plus driving distance dimensions and a `solveSketchConstraints` solver.
- Sketch inference (`SketchInference`) for cursor snapping.
- Push/Pull (offset-face feature).
- Linear pattern, mirror, rotate, move/copy, duplicate.
- Miter cut, join bodies, body boolean (union/difference/intersection).
- Wood joints: dado, rabbet, mortise & tenon, bridle, finger joint, etc.
- Linear & circular pattern, move/copy triad gizmos.
- Bake-body snapshot feature for independent copies.
- Move vertex (guarded planarity).
- Placement solver (`PlacementSolver`) for point-to-point and rotate-about-edge.
- TransformBodies (rigid placement via references).

### UI / interaction (Phase 5–6, complete)

- Compact, collapsible sidebar with sections: Selection, Model browser, Properties, Diagnostics, Woodworking, Sketch, Recent files, Assembly.
- Persistent workspace preferences (collapsed/expanded state, quick-start dismissal) — survives reload.
- Command palette (`Ctrl+K`) with full search and ranked results.
- Compact toolbar with category chips, primary work tools, hidden chrome tools.
- Sticky contextual task panel with universal Enter/Escape contract.
- View cube (six orthographic + iso) with keyboard shortcuts (T/F/R/B/L/U/Iso).
- Grid with major/minor spacing, grid snap, perspective toggle.
- Model browser with feature tree, body hierarchy, components/instances, visibility/lock toggles, rename, suppress, delete with dependency protection.
- Diagnostics panel for failed features.
- Sub-object selection (body/face/edge/vertex modes).
- Face, edge, vertex selection overlays with hover and persistent selection feedback.
- Translation triad gizmo, body rotate gizmo, move-vertex gizmo, push-pull gizmo.
- Welcome overlay (Quick Start) for first-run users.
- Accessibility: keyboard navigation, ARIA roles, screen-reader landmarks, no a11y violations on first-run workspace.
- Viewport grain-direction arrows that follow rotated bodies and component instances.

### Woodworking outputs (Milestone 09, complete)

- Tolerance-aware board measurement (`Measurements`, `MeasurementToolSession`).
- Material/grain metadata (`BodyWoodworkingMetadata`).
- Cut list CSV export (`CutList.ts`).
- Orthographic SVG/PDF/DXF shop drawings (`ShopDrawingSvg.ts`, `ShopDrawingPdf.ts`, `ShopDrawingDxf.ts`).
- Material catalog (`Materials.ts`).
- Manufacturing operation tracking (`ManufacturingOperation.ts`).

### Reliability (Milestone 10, complete)

- Schema migration `0.1.x → 0.2.0` (`Migrations.ts`).
- Autosave with rolling backups and corruption recovery (`AutosaveManager.ts`).
- Per-feature rebuild instrumentation, `getInteractionDiagnostics`.
- Reference benchmark for 200-feature workload (`ReferenceBenchmark.ts`) with 60-frame viewport budget.
- Performance: `getInteractionDiagnostics` reports rebuild counts, mesh cache hits, transform preview updates.

### Modularization (in progress)

- `src/app/PanelChrome.ts`, `GizmoManager.ts`, `ModelBrowserController.ts`, `WoodworkingController.ts` extracted from `App.ts`.
- Plan: `plans/modularity_plan.md` and `plans/tool_workflow_reduction_plan.md`.
- Current `App.ts` line count: 9,432 (down from 9,000+ pre-extraction; further reduction planned).

## 2. Missing features (the gaps)

These are the features professional CAD users expect to find. They are listed in priority order for woodworking CAD specifically.

### High priority — required to be useful for real woodworking

| # | Feature | Why it matters | Implementation effort | Notes |
|---|---|---|---|---|
| 1 | **Fillet / Round** | Every board edge that meets another at 90° needs a fillet for safety, ergonomics, glue joints, and CNC tooling. Without fillet, the modeler cannot produce a real piece of furniture. | Medium (new feature `fillet`, must re-derive planar faces from rounded edges) | The v1 constraint is planar-only; v1 should support **edge-only constant-radius fillet** of convex edges by inserting new planar faces tangent to the original. This is consistent with the existing planar/prismatic constraint. |
| 2 | **Chamfer** | The companion to fillet: 45° edge break for case construction, soft edges, fastener clearance. | Medium (similar to fillet, simpler math) | Pair with fillet. Same constraint: planar output, constant distance. |
| 3 | **Shell** | Hollow out a solid to a wall thickness. Essential for boxes, drawers, enclosures. | Medium-High (requires face removal + offset of remaining faces; needs B-Rep kernel work) | High value, common in woodworking (drawer boxes, case bodies). |
| 4 | **Hole / Drill** | Counterbored, countersunk, through, blind holes for screws, dowels, hinge cups. | Medium (revolve-along-axis + boolean subtract, can reuse existing extrude-cut machinery) | Currently must be done as extrude-cut with a circular sketch; users expect a dedicated "Hole" dialog with fastener presets. |
| 5 | **Loft** | Connect two sketches with a ruled surface. Required for non-rectilinear furniture, tapered legs, slide shapes. | High (complex; the planar constraint is stretched) | Could be implemented as a planar-only loft: ruled surface between two parallel planar profiles, with all faces planar. Avoids general surface lofting while delivering a valuable feature. |
| 6 | **Coincident/Equal dimension constraints in sketch** (current state: horizontal, vertical, parallel, perpendicular, equal, fixed, driving distance) | The list is good; verify it covers the **cornerstone sketch constraints** users expect: tangent (with arcs), symmetric, mid-point. | Low (constraint solver extensions) | If the modeler will ever support arcs, tangent is required. Today it's "no arcs" so the gap is theoretical. |
| 7 | **Circular / Path pattern** | The modeler has linear pattern; users expect a circular pattern around an axis. | Medium (sketch is the path or a separate axis) | Already mentioned in `types/FeatureType` (`pattern_circular`) but no feature implementation. |

### Medium priority — improves daily usability

| # | Feature | Why it matters | Effort |
|---|---|---|---|
| 8 | **Fillet/Chamfer preview while dragging the radius** | Match the existing universal Enter/Escape contract. | Low (mirrors Push/Pull preview). |
| 9 | **Improved sketch: arc, circle, polygon, spline, offset curve, trim, extend** | Sketching without arcs is a major limitation. Even constrained circular holes must be drawn as polylines or 4-segment rectangles. | High. The roadmap mentions a "Phase 3: Professional sketching" — this is largely the missing item. |
| 10 | **Named user-defined coordinate systems / datum planes** | For aligning cuts to arbitrary orientations. The construction plane is referenced from world or face; users expect a free datum. | Medium. |
| 11 | **Construction geometry in sketch (reference lines)** | Distinguish reference from real entities, common in all sketch tools. | Low-Medium (already partially supported via `entity.isConstruction`). |
| 12 | **Mirror about a custom plane (not just world/face)** | Currently plane reference is world or face. Users want a 3-point plane or a sketch-derived plane. | Low. |
| 13 | **Rib / Web feature** | Thin structural member between two sketches. Optional in woodworking. | High. |
| 14 | **Multi-body boolean across non-touching solids (fuse/split)** | The current `BodyBooleanFeature` requires overlapping solids. For non-touching bodies, users want to **join as one body** without merging volume (already supported as `joinBodies`) and to **fuse into one solid** (supported as union). The edge case is **split**: cut one body by another without volume merging. | Medium (extends existing kernel). |
| 15 | **Section view** | Cut a body with a plane to see inside. The drawing export already produces ortho views; an in-viewport section view is a common ask. | Medium. |
| 16 | **Interference / collision check between components** | Common in assembly work. | High (B-Rep intersection is expensive). |

### Lower priority — competitive parity but not required for MVP

| # | Feature | Effort |
|---|---|---|
| 17 | **Revolve (lathe)** | Out of scope (planar-only constraint). |
| 18 | **Sweep** | Out of scope. |
| 19 | **Thicken** (convert face to solid with thickness) | High. |
| 20 | **Surface modeling** | Out of scope. |
| 21 | **Mesh modeling** | Out of scope. |
| 22 | **Generative design** | Out of scope. |

| 26 | **3D printing export** (already partially covered by STL/OBJ? verify) | Low if files already supported. |

## 3. UX pain patterns (rooted in real professional CAD user complaints)

Across Fusion 360, Onshape, SolidWorks, FreeCAD, and SketchUp Pro, the **recurring complaint categories** (from forum threads, Reddit r/CAD, r/Fusion360, r/Onshape, r/SolidWorks, and user feedback) are:

### 3.1 Feature discoverability

> "I didn't know that tool existed."
> "The toolbar is overwhelming; I can't find what I need."

**Current state in this modeler:** 40 commands in `CommandCatalog.ts` distributed across 7 toolbar groups (Create, Transform, Combine, Edit, Assembly, Output, View, File, Help). A first-run user sees ~30 buttons. The Quick Start overlay helps on first run but is dismissed forever after one click. The command palette (`Ctrl+K`) exists but isn't surfaced in the toolbar.

**Recommendation:**
- **Add a "Discoverability" tooltip on every command** that shows the keyboard shortcut and a one-line description (already in title attribute; verify aria-label).
- **Re-show the Quick Start overlay on the 5th and 20th session** ("You've made progress! Here are some new things to try."). A pattern: nudges the user to features they've not used yet.
- **Add a "What's new" / feature spotlight** when a new feature is added.
- **Add a "Learn the modeler" / guided tutorial** that walks the user through Box → Sketch → Extrude → Fillet → Cut. Even a 5-step tour would dramatically reduce day-1 confusion.

### 3.2 "It broke my model"

> "I changed a parameter and now half the references are red."
> "I can't figure out which feature broke the model."

**Current state in this modeler:** This is **already well-served**:
- Reference resolver with signature-based fallback matching.
- Diagnostics panel with severity levels.
- Fail-closed semantics.
- The user can suppress downstream features to roll back.

**Recommendation:** Verify the diagnostic message copy. The current copy in `Diagnostics.ts` is technical. Users want messages like "The face you referenced in **Extrude 3** was removed when you changed **Box 1**'s width. Try [Restore Box 1 width] or [Pick a new face]." This is a copy/UX pass, not a re-architecture.

### 3.3 Performance

> "My model takes 30 seconds to rebuild."
> "Selection lag with 200+ features."

**Current state:** Per-feature rebuild instrumentation exists; `getInteractionDiagnostics` reports rebuild counts. The 200-feature browser performance budget test exists. RenderMeshCache hits are tracked. The modeler is **explicitly fast for the woodworking scope** and is benchmarked.

**Recommendation:**
- Continue enforcing the existing performance budget.
- Add a "performance profile" report on save (rebuild time, mesh cache hit rate, vertex count, body count).
- For users on lower-end hardware, add a quality-vs-performance toggle (lower mesh resolution when dragging).

### 3.4 Selection and direct editing

> "I can't click on a face in my assembly."
> "Move vertex breaks my model."

**Current state:** Sub-object picking is implemented (body/face/edge/vertex). Move vertex is planarity-guarded. The drawing tests show face selection works for primitives.

**Gap:** The **edge hover test** in the e2e suite is **currently failing**. This is a real UX bug. The face hover works, but moving from face mode to edge mode does not show the edge hover overlay. Users will see face highlight when they want edge highlight, and may not realize the mode changed.

**Recommendation:** Fix the edge hover regression (small, but high user-trust impact). Investigate the `edgeOverlayRole === 'hover'` scene query — it currently returns `null` even when `selectionMode === 'edge'`. The `updateEdgeHoverPreselection` function exists but the `hovered` state stays `null` in tests.

### 3.5 Toolbar / viewport congestion

> "The toolbar takes up half the screen."

**Current state:** The toolbar is collapsible per group. Mobile viewport (390x844) and tablet (768x1024) viewports are tested and pass. The left/right sidebars can collapse to rails.

**Recommendation:** Add a **floating radial menu** for selection actions (Right-click on a body → Move / Copy / Delete / Properties). This is a 3D modeler pattern (Blender, Maya, Rhino) and is missing here. Right-click currently does nothing in the viewport.

### 3.6 Onboarding and empty-state

> "I opened the modeler and didn't know what to do."

**Current state:** Welcome overlay (Quick Start) exists. Three buttons: Board, Sketch, Open. The `first run` test passes.

**Gap:** The Welcome overlay only appears **once** (it stores `quickStartDismissed` permanently). A user who dismisses it accidentally loses it forever.

**Recommendation:** Add a "Show me Quick Start again" link in the Help menu. Allow dismissing to be a choice, not a one-way door.

### 3.7 Keyboard ergonomics

> "I have to use the mouse for everything."

**Current state:** Comprehensive keyboard shortcuts: B (Box), S (Sketch), E (Extrude), C (Cut), P (Push/Pull), F (Face sketch), L (Pattern), M (Mirror), J (Group), I (Instance), Shift+G (Component), Shift+V (Move vertex), Shift+R (Rotate), Shift+J (Joint), V (Vertex mode), Ctrl+D (Duplicate), Ctrl+Z/Y (Undo/Redo), Ctrl+G (Grid), Ctrl+P (Projection), Ctrl+R (Reset view), Ctrl+K (Palette), Ctrl+Enter (Apply), Ctrl+N/O/S (File).

**Gap:** No **mouse-only path** for some operations. The translate triad gizmo for Move/Copy is mouse-driven, but most other commands require keyboard.

**Recommendation:** A right-click context menu in the viewport (mentioned in 3.5) would resolve this.

### 3.8 Undo/redo clarity

> "I undid but my selection didn't go back."
> "Redo doesn't work for parameter changes."

**Current state:** `undoLastChange` and `redoLastChange` exist. Tests show undo cancels active previews. Selection state is restored (mentioned in Phase 5 acceptance criteria).

**Recommendation:** Audit whether **tool session cancellation vs undo** are well distinguished. Currently Escape cancels a tool session (no undo entry); Enter commits (creates one undo entry). Users may press Ctrl+Z after Escape and find nothing to undo. Add status-bar text: "Preview canceled — no history entry" (which already exists). Verify it appears in all preview-cancel paths.

### 3.9 The "I don't know what this parameter means" problem

> "What's a *feature ID*? Why is there a *bodyRef*?"

**Current state:** Properties panel renders raw parameters for advanced features (WoodJoint, Placement, TransformBodies).

**Recommendation:** Add a **"Learn more"** link in the property inspector that opens the corresponding help page. Or render the parameter as a sentence ("Translate Box 1 by 2 inches along the X axis") instead of a form. This is a major UX win for a domain-specific tool.

### 3.10 "Where is the file I just saved?"

> "I saved but can't find the file."

**Current state:** `RecentFilesPanel.ts` exists. `RecentFilesStore.ts` exists. The "Recent files" section is hidden if there are no recent files.

**Recommendation:** Verify the section toggle is always visible (or surfaced via Help menu) so users can find it. Add an "Open file" command in the File menu (currently a button in the Quick Start overlay but not in the persistent UI).

### 3.11 Visual feedback for what the system is doing

> "Is it rebuilding?"
> "Did my click register?"

**Current state:** Status bar shows state changes. `getInteractionDiagnostics` tracks events. `ui:status` events are emitted on every important transition.

**Gap:** No **progress indicator** for long rebuilds. For a 200-feature model, a rebuild could take several seconds; the user has no visual feedback beyond a frozen viewport.

**Recommendation:** Add a non-modal rebuild progress indicator (a small "Rebuilding… N/M" badge in the status bar). This is a low-effort, high-trust win.

### 3.12 "Why is my model invisible?"

> "I added a body but it didn't appear."

**Current state:** Bodies can be hidden via the model browser. The viewport shows the rendered scene. `isBodyVisible` checks for hidden state.

**Recommendation:** When a body is hidden, the model browser should show a "hidden" indicator. When a body is added but its parent component is hidden, show a chain ("Hidden because parent component X is hidden"). The current state may already do this — verify.

## 4. Architectural observations

### 4.1 `App.ts` is still 9,432 lines

The modularity extraction has moved PanelChrome, GizmoManager, ModelBrowserController, and WoodworkingController out. The remaining ~9,400 lines is the "context-task + preview-session helpers" cluster flagged in `plans/tool_workflow_reduction_plan.md` as the connective hub that writes `this.features` directly.

**Recommendation:**
- **Land A1 (Copy/Duplicate Independence) and A2 (other tool flows) before the cluster-3 extraction.** The plan is right that A1 will simplify cluster 3.
- **Set a hard line at 7,000 lines for `App.ts` post-extraction.** Anything above that should be flagged in PR review.
- **The cluster-3 extraction is gated and risky** — it owns the only non-core `PreviewTransaction` and the document rebuild coordinator. Do it in a dedicated session, not opportunistically.

### 4.2 The e2e test that the user is currently chasing

`tests/e2e/modeling-workflows.spec.ts:611 — "face, edge, and vertex modes provide hover and persistent selection feedback"` is **failing** in the current state. The face hover works; the edge hover does not produce an `edgeOverlayRole === 'hover'` child in the scene. The `updateEdgeHoverPreselection` function in `App.ts:4522` does call `ensureEdgeSelectionOverlay().setHoveredEdge(body, edgeId)`, but the test sees `hovered: null` in the overlay.

This is the **most actionable single bug** in the project right now, and it's exactly the kind of UX issue that makes professional users distrust the tool.

**Recommendation:** Investigate why `setHoveredEdge` doesn't fire or doesn't persist. Likely suspects:
- The pointermove event is not being routed in edge mode (the route at `App.ts:4494` checks `selectionMode === 'edge'`, which is correct, but the `clearHover()` in the line above at `App.ts:4501` is called **after** the edge check — that should be fine).
- `isVisible()` returns false because the scene query happens from a different scene reference.
- The `rebuiltBodies` map is empty by the time the hover fires (rebuild race).

### 4.3 Tests are well-organized but could be stronger in two areas

- **Snapshot tests for `.modeller` files** — the file format is JSON; a `save → load → byte-equal` invariant test would catch migration regressions early. The schema migration test exists but is on individual features.
- **Property-based tests for `solveSketchConstraints`** — constraint solvers are notorious for edge cases. Property-based tests with random sketch inputs would catch regressions that hand-picked cases miss.

### 4.4 Feature count vs. test count

1105 unit tests for 40 commands is **~27 tests per command**. That's healthy. The e2e suite is **62 tests** — **~1.5 per command**. That is **low** for a CAD tool where each command has a complex interactive UX. Most professional CAD tools have 5–10 e2e tests per command.

**Recommendation:** For each new feature added (fillet, chamfer, shell, hole, loft), write **at least 3 e2e tests**: preview, commit, escape. For the **top 10 existing commands** (Box, Sketch, Extrude, Cut, Push/Pull, Pattern, Mirror, Move, Duplicate, Miter), audit whether they have full Enter/Escape + preview coverage. The recent `tool_workflow_reduction_plan.md` makes the right call here.

## 5. Prioritized recommendations

The recommendations are sorted by **user impact × effort**. Items higher on the list are the best ROI.

### Tier 1 — must-do (user trust + workflow completeness)

1. **Fix the edge hover regression** in `updateEdgeHoverPreselection` (highest user-trust impact; ~1 day).
2. **Add Fillet feature** (constant-radius, edge-only, convex-edges, planar output). Reuses the existing B-Rep kernel; inserts new planar faces. ~2 weeks.
3. **Add Chamfer feature** (symmetric 45° edge break). Mirrors fillet; ~1 week.
4. **Add Shell feature** (hollow out, set wall thickness). ~2 weeks.
5. **Add right-click context menu in the viewport** (Move / Copy / Delete / Properties / Hide). ~3 days. Resolves several UX complaints at once.
6. **Add a non-modal rebuild progress indicator** for long rebuilds. ~1 day.
7. **Surface the "Show Quick Start again" link** in the Help menu (re-showable onboarding). ~1 day.

### Tier 2 — high value (breadth for real woodworking)

8. **Add Hole feature** (drilled, counterbored, countersunk; with fastener presets). ~1 week.
9. **Add Circular Pattern feature** (`pattern_circular` is in the type union but not implemented). ~1 week.
10. **Add STEP import/export** (industry standard). ~2 weeks. Without STEP the modeler is an island.
11. **Add STL/3MF export** (3D printing). ~3 days.
12. **Add Mirror about a custom plane** (not just world/face). ~3 days.
13. **Add a guided tutorial** (5-step walkthrough: Box → Sketch → Extrude → Fillet → Cut). ~1 week. This is the single biggest day-1 UX win.

### Tier 3 — quality (UX polish)

14. **Diagnostic message copy pass** — translate technical errors to actionable advice with the source feature name. ~3 days.
15. **Render parameters as sentences** in the property inspector ("Translate Box 1 by 2 inches along X"). ~1 week.
16. **Add a performance profile on save** (rebuild time, mesh cache rate, body count). ~3 days.
17. **Audit and fix the depth of e2e coverage** for the top 10 commands. ~1 week.
18. **Reduce `App.ts` to < 7,000 lines** via the cluster-3 extraction in `plans/tool_workflow_reduction_plan.md`. Dedicated session.

### Tier 4 — competitive parity

19. **Loft feature** (planar ruled surface between two parallel profiles). ~3 weeks.
20. **Section view** (cut by a plane to see inside). ~2 weeks.
21. **DXF sketch import** (let users start from existing drawings). ~2 weeks.
22. **Interference check** (collision detection between components). ~3 weeks.

### Tier 5 — out of scope for v1 (per project constraints)

Revolve, sweep, thicken, surface modeling, mesh modeling, FEA, CAM, rendering, generative design, branching history, configurations.

## 7. Top 5 things to ship in the next release

## 8. What I did NOT find

- **No curves.** The planar-only constraint is intentional and is documented in `CLAUDE.md`. Don't change this.
- **No revolve.** Out of scope per the milestone definitions.
- **No CAM / FEA / rendering.** Out of scope.
- **No real-time collaboration.** Onshape's killer feature. Out of scope for v1.
- **No mobile-first design.** Mobile viewport passes the test, but the UX is desktop-first. This is acceptable.
- **No undo for navigation (camera moves).** Camera moves don't appear in the history. Some users expect them to. This is intentional; not a bug.

## 10. Closing recommendation

The modeler is **closer to a real product than it appears**. The architecture is sound, the professionalization roadmap is nearly complete, the testing is thorough, and the woodworking niche is well-served. The biggest opportunity is **closing UX gaps and shipping fillet + chamfer** — the two operations users will reach for first and find missing.

Do not expand to STEP, Loft, or Section View before the edge hover bug is fixed. The user's first impression of a CAD tool is the responsiveness of selection feedback, not the depth of the export menu.
