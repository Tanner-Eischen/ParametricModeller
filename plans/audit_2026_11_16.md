# Implementation audit — 2026-11-16

Scope: local source, plans, automated CLI checks, and targeted runtime probes at commit `4c20a6c`. No browser or platform UI was opened. This is an audit, not an implementation change. Temporary probes were removed after execution.

Follow-up implementation and verification are recorded separately in [audit fixes](audit_fixes_2026_11_16.md). The observations below remain the original baseline.

The next release should prioritize data preservation, correct manufacturing output, and completing or disabling exposed unfinished commands. The older September audit's feature-expansion recommendations should not drive the next sprint without reconciliation against the current implementation and planar-only contract.

## Findings, ordered by recommended delivery priority

### 1. P1: Document replacement can lose unsaved work and recovery

Source: `src/App.ts:7427` (`newDocument`), `src/App.ts:7470` (history reset), `src/App.ts:9463` (`seedDocumentHistory`); Open uses the same seeding path at `src/App.ts:7551`.

New replaces the active document and seeds fresh history without checking dirty state. Seeding also cancels the previous pending autosave. An actual App-method probe started with a dirty document and pending debounced autosave, then invoked New. The result was Untitled, no undo, no pending autosave, and no recovery records.

Fix: put New, Open, and Recent behind one document-transition service. Resolve dirty changes explicitly, preserve the outgoing recovery snapshot, and handle storage failure before replacing state.

Acceptance: dirty-document transitions support save/discard/cancel; cancel preserves the entire document and history; a recovery-write failure cannot silently discard edits; successful transitions preserve recoverable outgoing work according to a documented policy.

### 2. P2: Async save marks the wrong revision clean

Source: `src/App.ts:7375` captures a snapshot; `src/App.ts:7381` marks the current history entry clean after awaiting I/O.

An actual App-method probe began saving revision 1, committed revision 2 before I/O resolved, and then completed the save. Revision 2 remained in memory but `isDirty()` became false even though it had not been saved. The same code also applies the completed save's path to whichever document is current.

Fix: associate each save with the captured document identity and history entry. Completion must update only that document/revision, with defined ordering for concurrent saves.

Acceptance: test delayed save plus edit, undo, document replacement, and overlapping saves. Newer unsaved work must remain dirty; completion from a previous document must not change the new document's path or status.

### 3. P1: Rotational placement corrupts board-local dimensions

Source: `src/App.ts:1998`–`2021` handles orientation inheritance for Rotate Body and Mirror but not Transform Bodies; `src/features/placement/TransformBodiesFeature.ts:154` rotates geometry.

A probe invoked the actual App metadata resolver for a tagged 10 × 2 × 1 board copied using a 90-degree Z Free placement. Its grain axis remained `[1,0,0]`; `measureOrientedBoard` reported length 2 and width 10. This can mislabel cut-list dimensions and grain direction. Oblique placements also warrant tests for inflated stock extents.

Fix: propagate grain and thickness axes using the same resolved transform as the geometry, including reference-based placements. Give generated bodies explicit source lineage and transforms so metadata inheritance does not need separate feature-specific guesses.

Acceptance: rigid moves, rotations, copies, and component placement preserve board-local dimensions and stock volume; mirrored grain/thickness conventions are explicit; cut-list and drawing outputs agree after rebuild and save/load.

### 4. P1: Exposed Hole and Fillet commands are unfinished

Sources:

- `src/features/hole/HoleFeature.ts:68` stores a body ID in `refsIn`, where the graph expects a feature ID. A valid box-to-hole history produced `MISSING_DEPENDENCY`. The handler at line 78 returns successful empty geometry.
- `src/features/fillet/FilletFeature.ts:123` returns the original body as a successful output without replacement IDs. A valid box-to-fillet rebuild produced two bodies sharing one body ID and no changed geometry.
- `src/App.ts:6186` and `6212` append these features directly, bypassing preview, rebuild, and history commit. UI defaults also omit the required face/edge selection.

Fix: disable these commands and make persisted unsupported operations fail closed with actionable diagnostics. Decide whether drilling is manufacturing annotation or modeled geometry. A true curved fillet conflicts with the current no-curved-surfaces contract; a planar chamfer must be specified and named separately.

Acceptance: no command advertises geometry it cannot create; unsupported operations cannot silently enter successful history; body IDs remain unique; every enabled modeling command supports preview/commit/cancel and undo/save/load.

### 5. P1: Circular Pattern has incorrect transforms and identities

Source: `src/features/pattern/CircularPatternFeature.ts:128` divides by `count - 1`; line 145 ignores the supplied center; the topology ID map at lines 152–161 is never applied. The command appends directly at `src/App.ts:6338`.

For a box whose first vertex was `[30,10,10]`, a pattern with `center=[20,0,0]`, count 3, and angle 360 produced copies at `[-30,-10,10]` and approximately `[30,10,10]`. This proves rotation around the world origin instead of the specified center and overlap of the last copy with the original. Copies also shared topology IDs.

Fix: apply pivot translation, rotation, and inverse pivot translation; define full-circle versus partial-arc spacing and symmetric layout; allocate deterministic feature/instance topology IDs; use the existing preview transaction lifecycle.

Acceptance: nonzero-center cases, no duplicate full-circle placements, symmetric and partial-arc cases, repeat patterns of the same source, unique topology identity, exact-body references, and commit/cancel/undo invariants.

### 6. P1: Assembly mates are not refreshed by normal rebuild

Static integration finding: `src/App.ts:6766` is the only call to `solveConstraints`, in constraint creation. Normal rebuild at `src/App.ts:7092` calls `rebuildWithComponents` without constraints. `src/ui/AssemblyPanel.ts:405` displays stored satisfaction flags.

Consequently, editing source dimensions can leave a previously satisfied mate's status detached from current geometry. This finding comes from call-path inspection; no runtime assembly regression was reproduced during this audit.

Fix: solve or revalidate mates inside the rebuild transaction, before accepting instance transforms and statuses. Invalid references should generate actionable diagnostics and follow the same last-valid-result policy as feature rebuilds.

Acceptance: dimension edits either preserve the mate through a new transform or fail closed; load/rebuild detects removed referenced faces; statuses reflect current geometry; repeated rebuilds are deterministic.

### 7. P2: Export implementations need completion before UI integration

Sources: `src/export/STLExporter.ts`, `src/export/MF3Exporter.ts`, `src/export/STEPExporter.ts`.

A plain-box runtime probe observed:

- STL produced six facets with four vertices each; the existing shared triangulator produced twelve triangles for the same box.
- 3MF output contained zero `<vertex>` or `<triangle>` elements and included literal `undefined`. It returns model text, not a packaged archive.
- STEP emitted `EDGE_CURVE(1, 2, #1, .T.)` and used edge records directly in `ADVANCED_FACE`; `#1` is a Cartesian point, not the expected curve/surface geometry. External CAD import was not attempted.

All three command IDs exist in `src/ui/CommandCatalog.ts`, but `App.ts` has no registered actions for them. The toolbar filters out definitions without actions. These are unfinished source modules, not verified user-accessible export workflows.

Fix: reuse the ordered-loop, hole-aware triangulation already available for mesh exports, validate generated data, and implement format packaging/schema requirements before registering commands. Preserve the distinction between model units and export units. Test STEP with a parser/importer rather than string snapshots alone.

Acceptance: box, concave profile, through-hole, rotated body, and multi-body fixtures round-trip through independent readers with matching bounds, orientation, and volume within tolerance. Reject incomplete geometry rather than silently skipping faces.

### 8. P2: The current coverage gate fails

Source: `vitest.config.ts:16` requires 78% branch coverage. The clean audit run passed all 1,105 tests in 134 files, but `npm run test:coverage -- --silent` exited with code 1 because branch coverage was 77.74%. Lines/statements were 66.36%; functions were 87.19%.

The unit coverage report records 0% line coverage for App and all three export modules, 0% for Hole, 18.91% for Fillet, and 16.81% for Circular Pattern. This does not measure browser-test coverage, which was not run. It does show that passing unit tests do not verify several of the affected integration paths. CI invokes `check:all`, so the same coverage result would block that gate; current remote CI status was not inspected.

Fix: retain meaningful regression tests for the defects above and restore the coverage gate without lowering its threshold or adding assertions that merely reproduce implementation details.

## Improvements after the correctness work

1. **Test command integration, not just feature helpers.** Add a table of supported commands and require each enabled command to have an implementation, valid references, preview/commit/cancel behavior, and persistence coverage. The new commands bypassing the lifecycle show why existing component tests are insufficient.
2. **Extract document lifecycle and metadata propagation first.** `App.ts` is 9,628 lines. These responsibilities have concrete correctness failures and bounded interfaces. Avoid a large mechanical refactor before adding regression tests. `src/app/WoodworkingController.ts` exists but is not referenced by App; the live implementation remains duplicated in App, so the modularity summary overstates integration.
3. **Strengthen geometry assertions.** Add unique body/topology identity checks, volume and oriented-dimension assertions, and rebuilt-output tests for MoveVertex. Its feature test file currently focuses on validation/factories and explicitly defers rebuild tests.
4. **Reconcile the project status.** `AGENTS.md` still reports Milestone 07 and 493 tests. September's audit describes some currently implemented modules as absent and recommends curved-operation breadth without resolving scope. Maintain one capability matrix: implemented, exposed, tested, incomplete, and intentionally unsupported. Distinguish static web distribution from an installer.
5. **Measure before performance refactoring.** The build warns about large chunks; the main application chunk is approximately 805 kB minified / 212 kB gzip. Preserve current performance budgets and use measured startup/rebuild costs to choose further lazy loading or extraction. This audit did not run browser performance checks.
6. **Then choose one planar-compatible product improvement.** A section view, clearly specified planar chamfer, or sketch/DXF import are candidates. Selection should follow actual woodworking workflows after the current output and lifecycle defects are resolved; they are not prerequisites to this repair sprint.
